## 六、Redis 增量需求

| 原始要求 | 实现与验证 | 状态 |
|---|---|---|
| 只增加 starter 和连接池 | 仅增加 `spring-boot-starter-data-redis`、`commons-pool2`，未引入 Redisson | 通过 |
| String key / JSON value | `RedisConfig` 配置 StringRedisSerializer 与 GenericJackson2JsonRedisSerializer | 通过 |
| Lettuce 连接池 | `application.yml` 已配置超时及连接池参数 | 通过 |
| 统一 key 前缀 | `RedisKeyConstants` 统一定义 `hospital:` 前缀 | 通过 |
| 登录 token 缓存与失效 | 登录写缓存；注销、禁用用户、过期后 token 失效 | 通过 |
| 号源缓存与 Lua 预扣 | `ScheduleSlotCacheService` 管理号源缓存并使用 Lua 原子扣减 | 通过 |
| 分布式锁 | 同排班使用 `SET NX PX` 加锁，Lua 校验持有者 token 后释放 | 通过 |
| MySQL 仍是唯一真相源 | Redis 只做加速与并发协调，最终以 MySQL 条件更新和事务结果为准 | 通过 |
| Redis 异常降级 | 停止 Redis 后并发预约仍成功运行，由 MySQL 行锁和条件更新保证不超卖 | 通过 |
